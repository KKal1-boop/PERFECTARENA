## Story cutscenes — decoded so far (2026-10-21)

Status: **not 1:1.** These are the facts the executable and the install establish, and what is still open.

**Confirmed in `arena/ARENA/ACD.EXE` (unpacked image, data segment `0x3B60`):**

- The staff-piece counter is the byte at `0xf77` (0–8). Pickup routine `0x1ecc0` increments it; `0xf77 >= 8` gates the palace. A second increment site (`0x24927`) runs after the palace stage.
- Speech clips are chosen by base ID plus that counter: `1294 + n` (`n` = 0–8, the `1302` group of 23 clips is the palace message) and `1392 + n - 1` (`n` = 1–8). Dialogue call sites: `0x1ed44`, `0x1f278`, routine `0x1ed9d`.
- Movie names present in the image (lowercase): `intro`, `scroll`, `chaosvsn`, `staff`, `king`, `nuking`, `vision`, `jagar`, `walk`, `aflc2`, `nujagdth`, `morph`. Each is loaded through a name pointer; the movie player is `2294:0895`, which calls `0:6546`.
- Call sites that play named movies: intro `0x125c`; scroll clue `0x12e3`, `0x134e`; morph `0x41bb`; walk → aflc2 → nujagdth `0x1f2d8`–`0x1f2eb`; king/nuking `0x1f30a`–`0x1f340`.

**Follow-up decode (2026-10-21):**
- `0x1aa` is written at `0x14432` (set to 0 during new-game setup, next to the setup of `0x1a4`), and clamped downward at `0x26bf6` against a value computed from `0x5ad` and `0xa844`. The gate `0x1aa >= 1` means a piece only queues a cutscene once `0x1aa` has been raised, so `0x1aa` is most likely a progression stage. Unconfirmed.
- `0xf7c` is set to 1 at `0x1eeba`, only when the pending flag `0xf76` is set and `0xf79` is set. It is read at `0x1eca3` and `0x1f064`. Its exact meaning is still open.

**Corrected and extended (2026-10-21), piece order:**
- The table is at **`DS:0x80EC` with `DS = 0x3BA0`** (linear `0x43AEC` in `acd-image.bin`). The earlier base `0x3B60` was wrong; the value `01 02 05 06 04 00 07 03` is confirmed at the correct address.
- The table is used as a **required-dungeon check**. Routine `0x1eed3` loads the current dungeon ID from `0xa46` (copied from `0x47e1`, set by the travel code at `0x27804`–`0x27807`, and from the caller's `0x12a8` at `0x2778b`). It compares that ID with `table[counter]` at `0x1eedc`. A match plays the piece's text at `0x80F4 + counter`. A mismatch shows message `0x519` and returns. So the game enforces the order of the eight pieces, and the table is that order.
- The first dungeon the table asks for is ID `1`. If IDs index the piece list (`Fang Lair=0`), the first required piece is **Labyrinthian**, not Fang Lair. That contradicts the port's `STAFF_DUNGEON_ORDER`, which follows UESP. This is **not yet resolved**: the ID scheme behind `0x47e1` (quest-list index, province index, or CITYDATA order) must be traced through `0x12a8`.
- Piece pickup at `0x1ecc0` (`0xf77` increment) runs only after `0x1eced`'s guard, and the cutscene gate `0xf76` is set from `0x1ec80`. The movie IDs are still behind overlay `0xa611`.

## Story cutscenes — timing, corrected 2026-10-21

Why the port's cutscenes ran shorter than the original's:

- **Narrated movies loop.** OpenTESArena's `TextCinematicUiState::update` wraps the animation back to its first image while the speech clips play. The scene ends when the last clip (`SPEECH/<key>_<nn><A|B>.VOC`) finishes. The port now loops the movie for the narration's length (`showMovie` with `narrationMs`), instead of holding the last frame.
- **Plain movies play once.** `CinematicUiState` ends at the last frame, so movies with no narration keep their frame-count timing.
- **Speech length is the file's own.** The dream (`TEMPLATE.DAT` key 1400, `VISION.FLC`) is 21 clips, 133.3 s, read with `vocSeconds`. The movie is 3.4 s, so it loops about 39 times.

What is not settled:

- **Caption timing is approximate.** OpenTESArena collapses the raw `\r\n` breaks in `TEMPLATE.DAT` into spaces, so its own page split is not a reliable reference for the original's pages. The port paces captions by text length across the narration.
- **The speech keys are wired (2026-10-21).** Every main-quest beat now plays: `1400` (the cell), `1500` (the level-2 dream), `1294`…`1301` (the dream after each piece), `1392`…`1399` (Tharn's answer), `1447` (the palace gate), `1404` (the Jewel), `1405` and `1407` (the Emperor). The cut `1302` (the Jewel briefing) is deliberately not shown. The faces are OpenTESArena's own naming: `VISION.FLC` for Ria, `JAGAR.FLC` for Tharn.
- **The DOS timing of plain movies is unverified.** OpenTESArena plays them once. Whether the original holds or loops them could only be settled by a runtime trace.

## The main quest, 1:1 — 2026-10-21

**What is now exact, and how it is held there.**

- **The words are the install's.** Every beat's text is `TEMPLATE.DAT`, read from this install and checked in as `game/storyLines.js`; `tests/unit/storyscript.test.mjs` re-reads the install and fails on any drift. The quest chain's ten stage texts are the same lines (`STAGE_TEXT_KEYS`: `1400`, `1294`…`1301`, `1447`).
- **The order is the original's.** `game/storyScript.js` encodes UESP's walkthrough and the executable's speech bases: the cell's dream (`1400`) → the first Staff dream on the first sleep after **level 2** (`1500`) → the next sleep's `1294` → a dream after each piece, `1294 + pieces` → Tharn's answer at the next encounter, `1392 + pieces - 1` (**all eight**, `1392`…`1399`; the last is played at the palace, which is the next encounter after Dagoth-Ur, before `1447`) → the palace gate (`1447`) → the Jewel's cry (`1404`) → the Emperor's thanks (`1405`) and the naming (`1407`) → `JAGARDTH.FLC` and `END01.FLC`.
- **A clue is a parchment, not a film; the escape is travel, not a film.** Both are now nothing at the pickup; the old `SCROLL.FLC`/`VISION.FLC` wiring at those events was this project's invention.
- **The clock is the speech's.** `arena/storySpeech.js` holds every clip of every beat, measured from `SPEECH/` with `vocSeconds`; `narrationMs(key)` is the sum. A narrated scene loops its movie for the whole narration and ends with the last clip (OpenTESArena's `TextCinematicUiState` law).
- **It speaks.** `playVocList` (`game/trigSound.js`) decodes and schedules the install's clips back to back under the picture; `showMovie` stops them the moment the scene is skipped or ends.
- **The dream is sleep's, and the ambush is the next encounter's.** `restIn` (tavern room) and the wilderness camp call the dream; entering the next level plays Tharn's vision. Neither stops the player at the chest.

## The story's beginning — start menu, the king's murder, Ria's explanation (2026-10-21)

The owner: *"Ria Silmane explanation cutscene should start when you escape the imperial dungeon otherwise the story is uncomprehensible and you are searching for staff pieces for no reason … then also use the king murdered cutscene … there is no start menu also in perfectarena and there should be."* Three defects, one cause: the beginning was wired to a **skippable UI sequence** instead of the game's own beats.

- **The start menu is Arena's title screen** (`scenes/startMenu.js`): the install's `TITLE.IMG` behind **Continue** and **New Game**. Continue resumes the save's own last place (`game/startFlow.js`'s `resumeParams`: a named city, a dungeon with its seed, or a named interior such as `START.MIF`); New Game runs the real new-game flow in this page, because a hand-picked Arena folder cannot survive a navigation. A plain launch reaches it; `?menu` is the dev door to it alone.
- **The start-up cards and the story are separate beats.** `STARTUP_STEPS` (`TITLE.IMG`, `QUOTE.IMG`, `SCROLL.FLC`, the three scroll pictures) plays before the menu, once per session; `NEW_GAME_STEPS` is `INTRO.FLC` — **the king's murder**, 76 frames — and it plays after creation on **every** new game (`scenes/newGame.js`). The old single `OPENING_STEPS` put the cards and the betrayal in one skippable sequence *and* gated Ria's explanation on whether that sequence had been skipped: pressing Escape at the title card silently swallowed the story.
- **Ria's explanation (`1400`) is owed by the save, not by a screen.** It is the main quest's **start cinematic**: OpenTESArena looks up the `MainQuest` text definition with progress 0 and plays it immediately after creation (`ChooseAttributesUiState.cpp`, before the world is entered), and its own words are the cell's — *"Look to the north wall of this cell. You will find a ruby key which will unlock the door."* The port now reads the save's ledger (`game/storyScript.js`'s `dueCellDream` over `dreamsSeen`), the start menu sets `cellDreamPending` (`game/save.js`) when a game actually begins, and the first level boot plays it once, over `VISION.FLC` with the install's 21 clips, and marks it seen **before** the movie so a reload cannot repeat it.
- **Placement: in the cell, before the escape.** That is what the text says and where OpenTESArena plays it; after the escape the same words would tell the player to look at a wall in a room they had left. What the owner asked for is met by making it **unmissable**: skipping the cards, reloading, or starting from an older save that never heard her no longer loses it — an existing save is given it once on Continue, at its next level.

## Tharn's minions — 2026-10-21

The install's own words make the attack part of the beat, not an optional extra: *"I will use the same dream bridge that she uses, sending my minions across time and space. Already they arrive, ones worthy of the attention you deserve. They will relieve you of the burden of the Staff piece you now hold"* (`TEMPLATE.DAT` 1392); *"my minions arrive"* (1396); *"my servants arrive"* (1397); *"even if you survive the creatures I have sent against you now"* (1398); *"My legions await"* (1399).

- **They are placed when the level is built** (`interior.js`'s `populate`): if a vision is owed (`dueAmbush`), `AMBUSH_MINIONS` of the level's own roster are spawned 3–8 cells from the arrival, on standable, reachable cells, marked with the beat's key. Being in the population step is what gives them their walk and attack sheets — a body added after `populate` has no figure.
- **They are roused when the vision ends** (`maybeAmbushScene`): `stirTheLevel` on that group only, so they walk to the player from wherever they stand while the level's ordinary creatures keep their bands. The palace is excluded, as its own `1447` scene is.
- **The vision waits for an encounter.** It only plays on a level with a bestiary (`levelInhabited`), so entering a shop or a tavern no longer shows Tharn's words in a room where no fight is possible; the next dungeon or stretch of country brings it, with the minions.
- **The count is stamped, not claimed.** `A.EXE`'s encounter table is not in this checkout (D11); three is this project's number (`encounters.js`'s `AMBUSH_MINIONS`), chosen so a level-2 character can answer it with the level's low-tier creatures.

**Remaining deviations — named, not hidden.**

1. **The page breaks inside a narration are approximate.** The captions are grouped by sentence length over the narration. The voice pairs are known (`00A`, `00B`, …), so the *scene* timing is exact; which words belong to which page is not recovered (OpenTESArena collapses the raw line breaks, and its page count does not match the clip pairs).
2. **The movie chosen for each beat is inferred, not read from the dispatch.** `VISION.FLC` for Ria and `JAGAR.FLC` for Tharn come from OpenTESArena's cinematic library (which names them as those characters' animations); the executable's own movie-by-event table lives in an overlay the earlier sessions could not extract. The order and the words are verified; the face is the best-evidenced choice.
3. **Voice playback reads through either door.** `playVocList` takes the scene's own `source`: a player's picked folder (whose `fileListSource` flattens `SPEECH/…` to bare names — the loader tries the path and then the base name) or the `/arena-local/SPEECH/…` dev door. The server source's loose-file index was the trap: it lists the root only, so its `getBytes` now skips the index for a name with a folder in it (that filter silenced the first attempt, and the browser suite's own voice check caught it). Measured in a headless page with a picked-folder `ArenaSource`: the `1295` dream schedules 10 clips, 61.76 s, no console errors, and a clip the folder lacks is a clean miss rather than a throw.
4. **The ending page is a port screen**, not an original one: it quotes the install's `1404`, `1405` and `1407` and records what this save did.
