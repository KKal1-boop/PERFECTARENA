# DEFECTS

## Building-exit camera regression, 2026-10-18

**D-71 — FIXED:** "the view shake[s] all around when you exit a building", reported
immediately after the scene-cache optimization. A cached boot can finish during an existing
animation-frame batch. Its first `requestAnimationFrame` timestamp predates the scene's
`performance.now()` baseline, so `dt` became negative. Damage-shake decay then **added**
shake (`screenShake - dt * 2.2`), and the simulation clock and motor accumulator ran backwards.
The regression probe in `tests/suites/doors.mjs` failed before the repair: first elapsed time
**−1.7807 s**, artificial shake **3.91754**. The loop now primes its baseline from its first
animation frame (zero elapsed) and bounds subsequent deltas to **0…0.1 s**; it does not disable
legitimate combat shake or discard the asset caches.

Verification: all **704 unit tests pass**; live-browser exit tracing recorded **1,188 frames**
with **zero shake and zero stationary-eye drift**; real E-key round trips through equipment,
tavern, house, temple and palace each passed 24 first-exit-frame checks with no console errors.
The new three door-camera checks pass. The broader doors suite remains **57/58** because its
older wilderness fixture no longer contains a crypt after the geography migration (also failed
before this repair). Movement passed **13/13** on an isolated rerun; a concurrent run failed its
wall-clock-based drawn-weapon comparison, so that combined run is not a pass.
